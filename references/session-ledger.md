# Interview Session Ledger

Use this structure when the user authorizes preserving an unfinished or completed interview. Adapt it to the material; omit empty sections. Do not turn it into a transcript.

## Session boundary

- Date and source conversation
- Why the interview started
- What the user asked the interviewer to do
- Current stopping reason and requested continuation behavior

## Main thread

- Current question being explored
- Last concrete event
- What has been established
- What remains unanswered

## Transformation traces

For each material change:

- Prior view or behavior
- Triggering question, fact, contrast, or counterexample
- User's response and correction
- Current view
- Classification: expression refinement / tacit recognition / cognitive correction / co-generated insight / inert knowledge / unverified hypothesis
- Evidence and confidence

## Stable interaction preferences

Record only preferences demonstrated or explicitly confirmed, such as desired directness, tolerance for challenge, question pacing, or ownership boundaries.

## Opportunity signals

- Repeated pain or overlooked ability
- Who experienced it
- Strongest observed behavior
- Current validation level
- Missing evidence

## Open branches

List meaningful branches not yet explored. Preserve the question that should restart each branch.

## Next entry

Write one concrete opening question that reconnects to the last lived event. Avoid starting the next session with a broad request to summarize everything.

## Evidence pointers

Link to the original thread, recording, files, projects, or diary entries when available. Keep raw evidence separate from the synthesis.
